# 基于知识图谱与RAG的青藏高原建设项目生态准入判定研究
##项目简介
本项目旨在构建一个轻量级、高可信的智能判定系统，以应对《青藏高原生态保护法》实施后，因政策文件体系庞大、层级复杂而导致的合规性判定效率低下难题。系统通过知识图谱技术，将国家法律、省级办法及地方清单中关于空间管控单元与产业类型的“禁止/限制/允许”逻辑关系进行固化，以解决传统人工查阅的痛点并避免大模型幻觉。用户仅需输入“地点+项目类型”，系统即可实现秒级响应，输出精准的合规性结论、可溯源的法律依据，并结合近三年法规趋势提供决策建议，从而为青藏高原的生态保护与行政审批提供严谨、高效的智能化辅助。

##环境配置
-python 3.12
-知识图谱数据库：Neo4j (需预先安装并启动服务，默认端口7474)
-向量数据库：FAISS(通过pip安装，无需独立服务)
-核心依赖库： langchain：用于构建检索增强生成(RAG)流程。
              neo4j：Python驱动，用于连接和操作图数据库。
              sentence-transformers：用于文本向量化(Embedding)。
              pandas：用于处理CSV/Excel数据。
##运行步骤
1. 环境安装与配置
2. 数据准备与入库
整理数据文件：
将整理好的图谱规则数据(rules.csv)放入项目的 data 文件夹。
将切分好的法律法规文本数据(laws.jsonl)放入项目的 data 文件夹。
确保术语映射字典(synonyms.json)已存在于 config 文件夹中。
构建知识图谱：
运行图谱构建脚本。该脚本会自动读取 CSV 文件，并将“管控单元”与“项目类型”的关系数据批量导入到 Neo4j 数据库中。
构建向量索引：
运行向量库构建脚本。该脚本会读取法律文本文件，将其转化为向量数据并建立本地 FAISS 索引，以便后续进行语义检索。
3. 启动系统服务
运行项目的主程序入口文件。
系统启动后，会自动初始化图数据库连接器和向量检索器，并加载术语映射字典，准备接收用户指令。
4. 交互与查询
输入问题：在命令行界面或 API 接口中输入您的查询内容(例如：“我想在三江源建个水泥厂”)。
自动处理：系统会自动执行以下流程：  术语对齐：将您的口语化表达转换为标准术语。
                                  双路检索：同时在知识图谱中查找硬性规则，在向量库中查找相关法律条款。
                                  政策约束感知重排序
                                  趋势分析：独立模块扫描近期法规变化，计算监管趋势。
                                  逻辑推理：大模型综合上述信息生成最终回答。
                                  查看结果：系统将输出包含“合规结论”、“法律依据”及“监管趋势建议”的完整报告。
5. 维护与更新
更新政策：当有新的法律法规发布时，只需将新文本加入数据文件，并重新运行向量库构建脚本即可。
优化术语：根据用户实际使用情况，收集高频的非标准词汇并更新到术语映射字典中，以提高系统的识别准确率。
